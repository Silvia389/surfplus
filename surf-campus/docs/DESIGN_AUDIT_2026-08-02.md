# SURF Campus 设计与交互审计

> 审计日期：2026-08-02
> 审计范围：`frontend/index.html`、`frontend/demo.css`、`frontend/demo.js`、首次登录、身份绑定、设置、树洞和移动端导航

## 审计结论

当前界面已经从“功能 Demo”进入可用的产品外壳：信息流保持单列阅读，资料、通知、活动和组队有明确入口；首次登录资料初始化是一个聚焦任务；主题切换、移动端导航、焦点态、减弱动态和高对比度状态都有对应实现。

## 约束检查

| 约束来源 | 检查结果 | 当前证据 |
| --- | --- | --- |
| Apple Design | 通过 | 资料弹层阻止误关闭；绑定权限从点赞入口直接进入身份页；移动端保留连续单列阅读；sticky topbar、底部导航和上下文侧栏保持空间一致。 |
| Emil Design Engineering | 通过 | 交互使用具体 transition 属性；按钮有按下反馈；点赞反馈缩短到 240ms；没有从 `scale(0)` 进入的常用 UI；动画支持 `prefers-reduced-motion`。 |
| Interaction Design | 通过 | 加载、空状态、错误、成功、禁用、只读和权限拒绝都有用户可见反馈；学校邮箱绑定表单把前置条件、后缀限制和权限结果放在同一条路径。 |
| Frontend Design | 通过 | 使用稳定的 token、受控分区、清晰的信息层级和移动端约束；页面主区不是营销式 Hero 或卡片墙。 |
| Codebase Design | 部分通过 | 认证资料、主题偏好和邮件发送已经形成可替换的后端接口；下一步仍应把 JSON 持久化抽成数据库 Adapter，减少 `main.py` 的业务聚集。 |
| TDD / Code Review | 已覆盖关键路径 | 已有认证、树洞、偏好 UI 冒烟；新增 `profile-onboarding-smoke.cjs` 覆盖资料弹层、Esc 防跳过、头像、主题和持久化。 |

## 动效审计

| Before | After | Why |
| --- | --- | --- |
| 点赞反馈 360ms，缩放从 0.72 到 1.18 | 点赞反馈 240ms，缩放从 0.84 到 1.08 | 点赞是高频动作，缩短反馈并减少弹跳，避免让操作显得拖沓。 |
| 首次资料弹层可以用 Esc 关闭 | 未完成资料初始化时阻止 `cancel` 事件 | 首次登录的必填任务不会被误跳过；保存成功仍然可以程序化关闭。 |
| 手机访客仍能看到可直接点击的点赞按钮 | 显示“绑定后点赞”，点击进入身份页，不发送点赞请求 | 权限限制在视觉和行为两侧保持一致，减少无效点击。 |

## 后续审美风险

- 当前页面仍有一部分旧登录体验使用硬编码浅色值；它在应用主题之前展示，因此不影响已登录主题，但后续可统一为 token。
- JSON 持久化适合本地 MVP，不适合多实例部署；切换数据库时需要保持 `/api/profile`、`/api/profile/preferences` 和认证接口的外部接口不变。
- 真实邮箱服务启用后，必须补发件人验证、模板、限流、失败重试、退信处理和密钥管理。
